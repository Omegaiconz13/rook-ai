# 03 — The skill pack and CLI, dissected

The MIT repo is the only part of Minara we can read source for, and it is the most directly reusable
thing they publish. Vendored at [`skill-pack/`](skill-pack/).

## Shape

```
skill-pack/
├── README.md                  # marketing + install one-liners + benchmark badge
├── skills/minara/
│   ├── SKILL.md               # 300 lines: routing, safety, the full command table
│   ├── setup.md               # per-harness workspace integration (Claude Code, OpenClaw, Hermes)
│   ├── scripts/version-check.sh
│   └── references/            # 17 files, 1,502 lines total, one per command family
└── scripts/
    ├── claudecode-minara-skill-setup.sh
    ├── openclaw-minara-skill-setup.sh
    ├── hermes-minara-skill-setup.sh
    └── gen-star-history.py
```

**One skill, not twenty.** They ship a single `minara` skill with 17 lazily-read reference files.
The alternative (a skill per capability) would make routing the agent's problem and blow the context
budget. This is the correct structure for anything that is really "one CLI, many verbs".

## The frontmatter is doing real work

```yaml
name: minara
version: "3.0.4"
description: "…Use when: (1) crypto tokens/tickers… (8) subscription/premium/credits."
metadata: { "openclaw": { "primaryEnv": "MINARA_API_KEY",
  "requires": { "bins": ["minara"], "config": [...] },
  "install": [{ "id": "node", "kind": "node", "package": "minara@latest", "global": true }] } }
```

Four things to copy:

1. **The description is a numbered trigger list**, not prose. That is what makes zero-shot activation
   work across harnesses that only see `name` + `description`.
2. **`requires.bins`** — the harness can check `minara` is installed before activating.
3. **`install`** — the host can install the CLI itself. Skill + binary are declared together.
4. **`primaryEnv: MINARA_API_KEY`** — the env-var auth path is declared, so headless use works.

## The three exclusions that keep routing honest

The description lists what triggers the skill. `SKILL.md` then spends two paragraphs on what must
**not** trigger it:

```
**Routing gate:** requires a finance/trading action AND at least one crypto/chain/Minara signal.
Do NOT activate for pure blockchain education ("explain Ethereum PoS", "how does Solana
consensus work").

**Stock ticker disambiguation:** AAPL/TSLA/NVDA with buy/sell intent → clarify whether the
actual stock (not available on Minara — suggest a broker) or a tokenized/crypto version.
```

Negative routing is the difference between a skill that helps and a skill that hijacks every
question containing the word "Solana". Minara ships it as prose in the body because frontmatter has
no field for it.

## Safety encoded as procedure, not advice

The most instructive part of `SKILL.md` is that safety is a **state machine the agent must walk**,
with explicit banned behaviours:

- **Analysis → Trade boundary**: never execute in the same turn as analysis output. Analysis first,
  then at most a suggestion, then wait.
- **Pre-confirmation checks**: run `balance` first and compare against the amount; check perps
  autopilot status and force a choice if on; resolve the chain if a token exists on several; split
  compound intents into separate confirmations.
- **The confirmation summary** is a fixed table (Action / Token / Amount / Chain / estimated output /
  recipient / balance / leverage / warnings), and **the response ends there**. No fund-moving call
  in that turn.
- **Banned**: `-y`/`--yes` on fund-moving commands; skipping the structured choice; fabricating a
  user's confirmation ("User selected A" generated by the model is called an *instant safety failure*).

Copy the wording. "Instant safety failure" is a useful severity label for an agent-facing doc.

## Anti-loop safeguards — the unglamorous part that makes it work

Interactive CLIs hang agents. Their rules:

1. Prefer non-interactive flags; always pass `--all`, `--symbol`, `--side`, `--size`.
2. **Max 1 retry**, then stop and report.
3. **Hang detection**: no new output for 15 s while awaiting input → kill, do not retry.
4. Never run a bare interactive command when a non-interactive form exists
   (`perps close --all`, never bare `perps close`).
5. For unavoidably interactive commands, gather all inputs first, then run with `pty: true` and feed
   answers in order.

Any agent that wraps a CLI needs all five. Rook's Ninth calls tools in-process rather than via a
subprocess, so items 3 and 5 do not apply — but 1, 2 and 4 map onto tool-call arguments and retry
limits directly.

## Lazy auth, and never turning a 500 into a login prompt

```
Do not run `minara account` when this skill is activated. Authentication is checked only when the
requested command actually needs account access.
If the CLI explicitly reports an authentication failure → auth-recovery.md, then retry once.
Do not turn a network, Cloudflare, or upstream API error into a login prompt.
```

Three rules that eliminate the single most annoying agent failure mode: nagging for login on every
activation, and re-authorising because an upstream 502 looked like a 401.

## Version check as a contract

`scripts/version-check.sh` is a **pure detector**: it prints `UP_TO_DATE`, `SNOOZED`, or
`UPGRADE cli:X->Y [skill:X->Y]` and exits. The *agent* decides how to present it. It honours
`~/.minara/.update-snooze` (epoch seconds, written by the agent on "snooze 1 week") and a 24-hour
cache at `~/.minara/.last-update-check`.

Separating detect from prompt is why this works in every harness — no TUI assumptions, no interactive
prompt in a script that may run under a non-tty agent.

## setup.md: the same skill, four host configs

`setup.md` contains conditional blocks: if running in Claude Code → append a `## Minara` section to
`~/.claude/CLAUDE.md`; if OpenClaw → append to `~/.openclaw/workspace/AGENTS.md`; similarly Hermes.
Each block contains a **routing rule** ("when the message involves any of these, prefer this skill
over web search"), a **proactive engagement** rule (vague finance question → use live data, not
generic advice), and a **memory** section (prefers live data; always confirms before fund-moving ops).

That is a portable pattern: the skill carries its own host integration instructions and asks the
agent to write them into whatever config file that host reads.

## Install scripts

`claudecode-minara-skill-setup.sh` is `set -euo pipefail`, checks node/npm, then three steps:
[1/3] install/upgrade the `minara` CLI globally via npm; [2/3] install or update the skill directory;
[3/3] write the CLAUDE.md integration. It prints CLI version, skill version and CLAUDE.md path at the
end. Idempotent, verbose, and readable — a good template. The README's recommended install is a single
`curl … | bash` handed to the agent as a prompt, which is the lowest-friction distribution channel
available in 2026.

## The command surface (what "one CLI, many verbs" actually looks like)

Reproduced from `SKILL.md`, because it is the best available map of Minara's capabilities:

| Area | Commands |
|---|---|
| Spot | `swap -s buy\|sell -t TOKEN -a AMT`, `transfer -c CHAIN -t TOKEN -a AMT --to ADDR`, `limit-order create\|list\|cancel` |
| Perps | `perps order -S long\|short -s SYM -z SIZE [-T limit -p PRICE]`, `perps positions`, `perps close --all\|--symbol`, `perps cancel`, `perps leverage`, `perps trades -d DAYS`, `perps autopilot`, `perps ask` |
| Perp wallets | `perps wallets`, `perps create-wallet`, `perps rename-wallet`, `perps deposit -a`, `perps withdraw -a`, `perps transfer`, `perps sweep`, `perps fund-records` |
| Research | `ask "Q"`, `research "Q"`, `discover search\|trending\|fear-greed\|btc-metrics [--type tokens\|stocks]` |
| Funds | `balance`, `assets [spot\|perps]`, `deposit spot\|perps\|buy`, `withdraw` |
| Account | `login --device`, `logout`, `account [--show-all]`, `config`, `premium plans\|status\|subscribe\|cancel` |

Read-only (no confirmation): `balance`, `assets`, `account`, `ask`, `research`, `chat`, `discover`,
`perps wallets`, `perps positions`, `perps trades`, `perps fund-records`, `premium plans|status`,
`config`. Everything that moves money is on the confirm list, enumerated explicitly in `SKILL.md` —
an allowlist, not a "be careful" instruction.
